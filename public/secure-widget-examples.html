🔒 Secure Chatbot Widget - Best Practices

⚠️ SECURITY WARNING: Never use URL parameters for sensitive data like user IDs in production!

✅ Secure Methods (Recommended)

1. localStorage (Persistent Storage)

Security Level: 🔒 Secure (client-side only)

Use Case: Remember user across browser sessions

// Set userId in localStorage localStorage.setItem('chatbot_user_id', '38137'); // The widget will automatically detect this
Best Practice: Clear localStorage when user logs out

Current: Not set

2. sessionStorage (Session-Only Storage)

Security Level: 🔒 Secure (cleared when tab closes)

Use Case: Temporary session data

// Set userId in sessionStorage sessionStorage.setItem('chatbot_user_id', '38137'); // Automatically cleared when browser tab closes
Best Practice: Use for temporary sessions, automatically secure

Current: Not set

3. Global Variable (Before Script Load)

Security Level: 🔒 Secure (if set before script loads)

Use Case: Server-side rendering or early initialization

// Set before loading the widget script window.CHATBOT_USER_ID = '38137'; // Then load the widget <script src="chatbot-widget.js"></script>
Best Practice: Set this before the widget script loads

Current: Not set

4. Meta Tag (Server-Side Rendering)

Security Level: 🔒 Secure (server-generated)

Use Case: Server-side rendering with user authentication

<meta name="chatbot-user-id" content="38137">
Best Practice: Generate this server-side based on authenticated user

Current: 38137 (set in this example)

5. postMessage API (Dynamic)

Security Level: 🔒 Secure (client-to-client communication)

Use Case: Dynamic user authentication

// Send userId via postMessage window.postMessage({type: 'SET_USER_ID', userId: '38137'}, '*'); // Or set multiple config options window.postMessage({ type: 'SET_CONFIG', config: { userId: '38137', buttonColor: '#ff0000' } }, '*');
Best Practice: Use after user authentication is complete

6. JavaScript API (Dynamic)

Security Level: 🔒 Secure (direct API call)

Use Case: After widget is loaded

// Use the exposed API window.ChatbotWidget.setUserId('38137'); // Or set multiple config options window.ChatbotWidget.setConfig({ userId: '38137', buttonColor: '#ff0000' });
Best Practice: Call after widget is fully loaded

Current config: Not loaded

❌ Insecure Methods (Development Only)

URL Parameters (NOT SECURE)

Security Level: 🚨 Insecure (visible everywhere)

Use Case: Development/testing only

// NOT RECOMMENDED FOR PRODUCTION https://yoursite.com?userId=38137 // Requires explicit permission <script data-allow-url-params="true" src="chatbot-widget.js"></script>
Security Risks:
  • Visible in browser history
  • Visible in server logs
  • Visible in referrer headers
  • Visible in network inspection tools
  • Visible in browser developer tools

🔐 Production Security Checklist

  • ✅ Never use URL parameters for sensitive data
  • ✅ Use server-side authentication when possible
  • ✅ Clear localStorage/sessionStorage on logout
  • ✅ Validate userId on server-side
  • ✅ Use HTTPS in production
  • ✅ Implement proper session management
  • ✅ Consider using JWT tokens for authentication
